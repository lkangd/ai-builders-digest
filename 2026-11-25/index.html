2026-11-24 04:52
New research from Replit on scaling laws for agent swarms.

We show that scaling the number of agents can yield dramatic performance gains, but unlike traditional scaling laws, more compute doesn't necessarily translate into better results, and how agents organize themselves matters.

- Given a fixed two-hour window, Opus 5.5 went from a 3.7x speedup on NumPy with one agent to 18.9x with 32 agents.

- GPT-6.2 Astra was the strongest solo agent but exhibited negative scaling beyond 8 agents.

- Models spontaneously developed different organizational structures. Decentralized swarms scaled better than those that relied on centralized coordination.

- The parallelizability of the problem was a strong predictor of swarm performance.

- Interestingly, individual model intelligence is a poor predictor of collective intelligence.

We’re also open-sourcing Optimization-Bench to advance research into this new dimension of inference-time scaling.

https://frontier.replit.com/throwing-headcount-at-the-problem/
译文
Replit 发布了关于 agent swarms 的 scaling laws 新研究。

我们表明，扩大 agent 数量可以带来显著的性能提升，但和传统 scaling laws 不同，更多 compute 并不一定带来更好的结果，agent 如何组织自己也很重要。

- 在固定的两小时窗口里，Opus 5.5 在 NumPy 上从 1 个 agent 的 3.7x 加速，提升到 32 个 agent 的 18.9x。

- 问题的可并行程度，是 swarm 表现的强预测因子。

- 有意思的是，单个模型的 intelligence 并不能很好地预测集体 intelligence。

我们还开源了 Optimization-Bench，以推进对这一新的 inference-time scaling 维度的研究。

Matt Pocock@mattpocockuk
Vercel Board has been lighting my brain on fire for the last few days

It's a genius idea, but I think most teams should build it from scratch

Basically just a private Slack workspace for your agents AND developers (which can even sync to Slack channels for better observability)

The idea (not necessarily Vercel's implementation of it) makes so many things simple:

1. Collaborative grilling

Each locally running agent has its own identity on the board. As does every human!

That means if you're grilling with an agent, and you need to ask someone a question, you just get your agent to ping them (or, ping their agent!)

2. Locally running agents

This setup feels awesome for connecting locally running agents to the rest of the organisation.

"Unread messages" could form a queue (Vercel board doesn't do this AFAIK) which would allow remote agents to ping messages to local agents, which would get picked up when they wake up.

This would allow seamless communication between remote and local, and aid companies looking to make the leap to remote agents.

3. Schedules

Want to schedule a cron? Just trigger a repeating message to an agent. I love how simple it makes the mental model.

4. Multi-vendor setups

Creating a vendor-agnostic version of this would be sweet - a seamless collaboration environment for all of your vendor-locked servers/harnesses.

5. Deterministic workflows as commands

One opportunity I see for Vercel Board is to allow for registering deterministic workflows as `/commands` - i.e. running review agents or implementer agents.

This would allow you to mix and match agents and workflows in a really lovely way, and agents could themselves trigger workflows which report back via the board.

Overall my brain is on fire, just wanted to share

https://vercel.com/blog/introducing-vercel-board
译文
过去几天，Vercel Board 一直让我脑洞大开

这是个天才想法，但我认为大多数团队应该从零自己做一套

本质上就是给 agents 和开发者共用的私有 Slack workspace（甚至可以同步到 Slack channels，以便更好地观察）

这个想法（不一定是 Vercel 的具体实现）让很多事情变得简单：

1. Collaborative grilling

每个在本地运行的 agent 在 board 上都有自己的身份。每个人也是！

这意味着，如果你正在和一个 agent grilling，需要问某人一个问题，只要让你的 agent ping 他们（或者 ping 他们的 agent！）

2. Locally running agents

这套设置在把本地运行的 agents 连接到组织其余部分时，感觉非常出色。

“未读消息” 可以形成一个队列（据我所知 Vercel board 还没这样做），让远程 agents 把消息 ping 给本地 agents，后者醒来时再接收。

这将实现远程和本地之间的无缝沟通，并帮助那些想迈向远程 agents 的公司。

3. Schedules

想安排一个 cron？只要向一个 agent 触发一条重复消息。我很喜欢它把心智模型变得这么简单。

4. Multi-vendor setups
