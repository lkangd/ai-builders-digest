2026-08-01 00:36 Quoted
The most common loop written in Linear is some variant this one (Issue > Agent > PR > Release)

~30% of our bugs make it all the way through this flow.

But there are some nuances to doing it -- The instructions should ask the agent to extensively research the root cause of the issue and to use Datadog and Sentry MCPs to gather more evidence.

It should only attempt to provide a fix if there's high certainty, otherwise you end up burning a lot of tokens.

If it thinks that more evidence would help it during its research, like asking the reporter to provide repro steps, etc, it should leave a comment on the issue requesting it.

Agents need to be told to following good practices, just like people!
译文
Linear 中最常见的循环是类似这样的变体（Issue > Agent > PR > Release）

我们大约 30% 的 bug 会一路走完这个流程。

但实际操作中有一些细微差别——指令应要求 agent 深入研究问题的根本原因，并使用 Datadog 和 Sentry MCP 收集更多证据。

只有在高度确定的情况下才应尝试提供修复，否则会浪费大量 token。

如果它认为更多证据有助于调研——比如要求报告者提供复现步骤等——它应该留下一条……

Starting today, Claude Code can capture work progress as an artifact, which turn Claude Code&#x27;s work into live, shareable visual pages— including PR walkthroughs, system explainers, dashboards, and release checklists—that update themselves as your session works. A Claude Code session can range from investigating an incident to refactoring a service to analyzing months of data. Artifacts translate the work into a web page anyone can open and explore, like a pull request walkthrough, a dashboard you can filter and sort, or even a release checklist that fills itself out as work gets done. Artifacts make it easier to collaborate on shared work, so teams can spend more time building and less time communicating status updates. Built on the context from your session Claude Code builds an artifact using the full context of your session, including your codebase, your connectors, and the conversation itself. A single incident page can bring together the failing test and the function behind it from your code, the error spike from a connected monitoring tool, and the root-cause reasoning from the session you just ran. With artifacts, you don&#x27;t need to wire up data sources or stand up infrastructure. You ask for a page, and Claude Code builds it from what already exists. Live pages that update in place When Claude Code updates an artifact, the open page refreshes in place and teammates see the updates the moment they’re published. Every publish is a new version at the same link, with version history so you can restore at any time, and a gallery lets you browse and manage all artifacts you&#x27;ve made. From our internal testing, one of our most common use cases has been debugging. These typically look something like: An engineer kicks off an incident investigation before standup. Claude Code works through the logs and publishes an artifact: a timeline, the suspect commits, and an error-rate chart. She shares the link with her team from the page header. By the time standup begins, Claude has republished it twice as the investigation progressed, incorporating the latest information. With artifacts, team members and stakeholders don’t have to "walk us through what the agent found" because they&#x27;re all looking at the same view, with the same context. Private to your organization Every artifact is private to its author by default. When you&#x27;re ready, share it with your teammates and your organization directly from the page. Artifacts are viewable only by authenticated members of your org and cannot be made public. Admins manage access with an org-level toggle and role-based scoping, set retention policies, and get org-wide visibility through the compliance API.
