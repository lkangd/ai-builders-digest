2026-10-15 14:45
Moving from chatting back and forth with agents, to having agents that you spin up in the background to do useful work for you is probably on the order of 100X or 1000X more token consumption than what we’re seeing today.

Most work right now is essentially rate limited by our ability to process and work with information. Moving data between systems. Reviewing a document. Looking through code for security issues. Processing log data to look for even patterns. Looking up information about a prospective client. Almost all of knowledge work is constrained by these steps, and AI has become a huge unlock to that.

So our first step was to use AI to do these individual tasks much faster for us. That was the chatbot phenomenon that we have been experiencing for the past 3+ years. But we can still then only augment the work that we remain in the loop for, and we’re highly limited by our ability to parallelize this work by our own bandwidth and context.

But where we’re going is quite different. As AI models continue to improve at incredible rates, we can hand off more and more work to the agent. First it’s letting the agent run with a harder problem. Then it’s giving a few agents multiple parts of a task at once. But we’re not far off from being able to throw an arbitrary number of agents at a problem and just say “come back when you’ve accomplished this goal”.

Now imagine that agent swarm for any problem we can think of. Protecting our codebases, data, and systems. QAing every change we make and make sure all our infrastructure is robust and does what it should. Looking through every document for potential risks. Auditing this company with vastly more data reviewed. And on and on. Most of this isn’t even replacing existing work we do, it’s all net new.

These agents will get deployed as swarms by people, by workflows, by triggers, and by other agents. And none of this would be possible if the models weren’t getting better, and if the cost of AI didn’t make it affordable. Both of those trends though are playing out. Now the next frontier is just having enough compute. But this is where it’s heading.
译文
从与智能体来回聊天，转向让你在后台启动智能体为你做有用工作，token 消耗可能是今天的 100 倍甚至 1000 倍。

现在大多数工作本质上受限于我们处理和运用信息的能力。在系统间搬数据。审阅文档。翻代码找安全问题。处理日志数据，寻找事件模式。查潜在客户的信息。几乎所有知识工作都受这些步骤制约，而 AI 已成为巨大的解锁力量。

所以第一步是用 AI 替我们更快完成这些单项任务。这就是过去 3 年多我们经历的聊天机器人现象。但我们仍然只能增强自己仍在环路中的工作，而且我们并行化这些工作的能力严重受限于自身带宽和上下文。

但我们要去的地方完全不同。随着 AI 模型以惊人速度持续改进，我们可以把越来越多工作交给智能体。先是让智能体处理更难的问题。然后是让几个智能体同时承担一项任务的多个部分。但距离能把任意数量的智能体扔给一个问题，并只说“完成这个目标再回来”，已经不远了。

现在想象一下，把我们能想到的任何问题都交给那样的智能体集群。保护我们的代码库、数据和系统。对我们做的每次变更做 QA，确保所有基础设施稳健、按预期运行。翻遍每份文档找潜在风险。用远超以往的数据审计这家公司。等等等等。其中大部分甚至不是取代我们现有的工作，而是全新的增量。

这些智能体将由人、工作流、触发器和其它智能体以集群方式部署。而如果模型没有变得更好，如果 AI 成本没有降到可负担，这一切都不可能。不过这两个趋势都在发生。现在下一个前沿就是拥有足够的算力。但方向就是这样。

Tool calls are the hidden bottleneck killing the AI coding speed.

Models are getting faster, but tests and builds still take time, making the agent spend more time waiting for tool calls to end than coding. @steipete's Crabbox is one interesting way to speed up your agent.

To make your agents faster, ask yourself:

1) Where is the time going? Measure which tool calls are slowing your agents down.

2) Can I run fewer checks? Select relevant tests instead of always running the entire suite.

3) Can I parallelize? Run independent tests concurrently.

4) Am I hitting CPU/RAM limits? Offload expensive work to other machines with tools like Crabbox.
